[README](README.md)。

- 描き手: `claude -p`（その時点の CLI の既定のモデル）。道具は `moonlight` CLI と
  Read / Write / Edit だけ。課題 8 つ。

- 直す前と後で、描き手・依頼文・課題・判定は同じ。

## 見つかったこと

**1. 書き出した SVG の文字が、エディタで開くと別の場所に出る**（`model-matches-picture` が 8/8 で落ちた）

モデルとエディタは `text x y` を文字の中心として扱うが、ヘッドレスの書き出しは
`text-anchor` / `dominant-baseline` を落としていた。ブラウザは (x, y) を左下として
描くので、同じ SVG がブラウザとエディタで違って見える。AI は文字の置き方を自分で
試し（`text t 60 40 Hi` を描いて `describe`）、モデルの説明どおり「中心」と結論して
いた。読み違えていたのは AI ではない。

**2. ラベルを図形に結び付ける手段が無い**（`label-follows` が新規の 6 課題すべてで落ちた）

エディタでは図形の中の文字は図形に結び付き、図形を動かすと付いてくる。シナリオ文法
には書き方が無く、AI は図形の上に `text` を置くしかなかった。図形を動かすと文字だけ
が取り残される。編集の 2 課題は、最初の図（エディタの形の SVG）のラベルが結び付いて
いたので落ちなかった。

**3. 矢印が描けない**（矢印を頼んだ 3 課題のうち、見た目の判定で 3 つとも落ちた）

モデルと SVG には矢じりがあるのに、シナリオで付ける方法が無かった。試走（下の
注記）では、AI は `arrow` を試して「unknown command」、ソースを探そうとして止められ、
最後は SVG を手で書き換えて `marker-end` を足し、CLI で保存し直していた。矢印の
3 課題だけで 92 ターン・$1.30。

**4. 文字に縁取りが付き、太く滲んで見える**

シナリオで置く文字には既定のスタイル（黒い 1px の縁取り）が付いていた。エディタで
置く文字には縁取りが無い。

**5. 書き間違えた数が黙って 0 になる**

`rect a 10 x 80 60` の `x` は 0 として読まれ、エラーにならなかった。

## 直したこと

- ヘッドレスの書き出しもエディタと同じく文字を中央揃えにする（1）
- `label <図形> <文字>`: 図形の中央に置き、図形に結び付けた文字（2）
- `arrow <id> x1 y1 x2 y2`: 終点に矢じりの付いた線。`join` は線と同じ（3）
- シナリオの文字はエディタと同じスタイル（縁取り無し）（4）
- 数を書くところに数でないものがあれば、行番号と引数の位置つきでエラー（5）
- `describe` はラベルを `label … on <図形>`、矢印を `arrow` と書く。CLI のヘルプに
  `arrow` / `label` / ドラッグの書き方と、座標の意味（矩形は左上、文字は中心）を足した

直したあとの AI は、`label` と `arrow` と `join` を使って一度で正しいシナリオを書いた
（cycle は 4 回の道具で完了）。

## 注記

- **回数が少ない。** 直す前は 1 回、直したあとは 2 回。直す前のふるまいの失敗は
  Moonlight の不具合による決定的なもので、正解の図でも同じように落ちる。揺れるのは
  主に矢印の見た目（AI が矢じりを手で足すかどうか）。
- **試走。** 最初の試走では、評価を走らせているセッションの環境変数（推論の深さなど）
  が描き手に漏れていた。そのときの AI は矢じりを SVG の手書きで足し、矢印の見た目は
  通ったが、ターンと費用が膨らんだ（8 課題で 133 ターン・$1.71）。本番の計測は環境
  変数を切り離して行った。
- **編集の課題の最初の図** はエディタが書き出す形の SVG を直接持つ。シナリオから
  作ると、その版の文法でできる図（ラベルが結び付かない図）にしかならないため。
